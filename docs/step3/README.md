## 기능 요구사항 명세
### 1. 주문 세션 및 임시 주문서 관리
- [ ] 장바구니에서 [주문하기] 클릭 시, 선택된 장바구니 ID 목록만 서버로 전송
- [ ] 서버는 전달받은 ID를 기반으로 DB에서 최신 상품 정보인 가격, 수량을 조회한 뒤 preorder 테이블에 저장하고 preorderId를 발급한다
- [ ] 주문 확인 페이지 진입 시 해당 preorderId를 바탕으로 주문 대상 상품 정보를 렌더링한다

### 2. 쿠폰 도메인 및 정책 검증
쿠폰 데이터는 DB에 하드코딩하여 서버가 중앙 관리한다.
- [ ] 쿠폰 정책:
- 5,000원 할인 쿠폰 (FIXED): 최소 주문 금액 100,000원 이상 시 적용
- 2+1 쿠폰 (BOGO): 동일 상품 2개 구매 시 1개 추가증정. 장바구니 내 단가가 가장 높은 상품에 우선 적용
- 무료 배송 쿠폰 (FREESHIPPING): 최소 주문 금액 50,000원 이상 시 적용 (도서산간 추가 배송비 포함 무료)
- 30% 타임 세일 쿠폰 (MIRACLESALE): 매일 오전 4시 ~ 오전 7시에만 30% 할인 적용
- [ ] 사용 가능 쿠폰 목록(`GET /coupons?preorderId={preorderId}`) 호출 시, 서버는 `preorderId`에 저장된 총액과 시간 조건을 기반으로 각 쿠폰의 disabled 여부를 판별하여 응답한다.

### 3. 복합 할인 계산
- [ ] 사용자는 최대 2개의 쿠폰을 동시에 선택 가능
- [ ] 사용자가 선택한 쿠폰 조합의 순열(A->B, B->A)을 시뮬레이션하여, 가장 할인액이 큰 조합을 도출
- [ ] 배송비는 기본 조건(10만 원 이상 무료) 판별, 도서산간 추가 비용(+3,000원)은 가격에 상관없이 배송비에 +3,000원, 쿠폰(FREESHIPPING) 적용 시 전액 무료 처리의 연산 순서를 따른다.

### 4. 결제 무결성 교차 검증
- [ ] 사용자가 최종 [결제하기] 버튼을 클릭할 때, 프론트엔드는 화면에 표기된 '기대 금액(expectedPrice)'과 함께 `preorderId`, `couponIds`, `isRemoteArea` 상태를 서버로 전송
- [ ] 서버는 클라이언트의 계산 값을 신뢰하지 않고, 캐싱된 임시 주문 데이터와 쿠폰 상태, 서버 시간을 기준으로 실제 금액을 자체 재계산한다.
- [ ] 서버는 `기대 금액 === 실제 금액`인지 비교
- 성공 시: 결제를 승인하고 DB의 상품 총수량(`totalQuantity`)을 차감, 장바구니 내역 삭제 후 주문 테이블(`order`)에 최종 기록
- 검증 실패 시 (400 / 409 Error): 쿠폰 기한 만료, 재고 부족, 클라이언트 변조 등으로 금액이 불일치할 경우 에러 메시지와 함께 콜백
- [ ] 프론트엔드는 검증 실패 시 쿠폰 목록을 최신화하거나 사용자에게 명확한 에러를 표기하는 복구 흐름을 제공
- [ ] 결제 성공 시 `GET /order/:orderId`를 통해 최종적으로 확정된 결제 정보를 렌더링

## 상태 설계
### 1. 서버(DB)에서 관리하는 데이터
- 상품 데이터: 상품 ID, 상품 이름, 상품 가격, 상품 총 재고, 상품 썸네일 주소
- 쿠폰 정보 (TYPE 및 자료형)
  - `BOGO`: n개 구매 시 동일 상품 수량 추가 증정
  - `DISCOUNT`: 고정 금액(`FIXED`) 또는 비율(`PERCENT`) 할인
  - `FREESHIPPING`: 배송비 무료 처리
  - `TIMESALE`: 특정 시간대에만 적용 가능한 비율(`PERCENT`) 할인
- 쿠폰 사용 검증 조건
  - 총 금액이 쿠폰 할인 금액보다 커야 하며, 최소 주문 금액 조건을 만족해야 함
  - BOGO 쿠폰 적용을 위한 동일 상품 최소 구매 수량 충족 여부
  - 쿠폰 만료일 경과 및 특정 시간대 해당 여부 확인
  - 현재 선택된 쿠폰이 2개 이하인지 여부

### 2. 클라이언트에서 관리하는 상태
- 사용자 인터랙션 상태 관리
  - 개별 상품 선택 여부 및 구매 수량 변경 상태
  - 적용할 쿠폰 선택 여부 상태
  - 산간지역 체크 여부
