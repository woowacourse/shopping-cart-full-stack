## 설계 원칙

- 프론트엔드는 금액 계산 로직을 갖지 않고, 서버가 계산한 결제 금액 미리보기 결과만 화면에 표시한다.
- 서버는 결제 금액 계산의 단일 책임자다.
- 프론트엔드는 쿠폰 체크/해제 또는 제주도 및 도서산간 지역 여부 변경 시 현재 선택 상태로 결제 금액 미리보기를 요청한다.
- "총 n원 할인 쿠폰 사용하기"의 `n원`은 서버의 결제 금액 미리보기 응답을 기준으로 표시한다.
- 상품 할인 쿠폰의 적용 순서는 `benefit.discountType`으로 판단하며, 서버는 `FIXED` 할인 적용 후 `RATE` 할인을 적용한다.
- 2+1 쿠폰의 무료 증정 상품은 서버가 계산한 `benefitItems`로 표현한다. 서버는 무료 증정 상품의 정가를 주문 금액과 상품 할인 금액에 함께 반영해 화면 금액과 실제 수령 수량의 정합성을 맞춘다.
- 제주도 및 도서산간 지역 체크 여부는 주문 생성 전까지 DB에 저장하지 않고, 결제 금액 미리보기 요청의 계산 입력값으로만 사용한다.
- 결제 금액 미리보기 요청이 성공하면 서버는 실제 적용된 쿠폰 ID 목록과 배송 조건을 PreorderStore에 저장한다.
- 주문 생성 시 서버는 preorder, PreorderStore의 적용 쿠폰/배송 조건, 쿠폰 정책, 서버 시간을 기준으로 결제 금액을 반드시 다시 계산한다.
- 프론트엔드는 결제 금액 미리보기 응답의 주문 금액, 상품 할인 금액, 배송비 할인 금액, 총 할인 금액, 배송비, 최종 결제 금액을 사용자가 본 금액 스냅샷으로 보관한다.
- 프론트엔드가 주문 생성 요청에 포함하는 `expectedTotalPaymentAmount`는 사용자가 화면에서 보고 동의한 금액 스냅샷 중 최종 결제 금액과 서버 재계산 금액이 같은지 확인하는 UX 검증 값이다.
- preorder는 캐시 최적화가 아니라 장바구니와 확정 주문 사이에서 사용하는 짧은 생명주기의 주문 세션이다.
- PreorderStore는 이번 단계에서 서버 인메모리 Map 기반 TTL 저장소로 구현한다.
- 서버 인메모리 PreorderStore는 서버 재시작 시 데이터가 사라질 수 있으며, 사라진 preorder는 만료된 preorder와 같은 복구 흐름으로 처리한다.
- 시퀀스 다이어그램의 임시 저장소 참여자는 외부 캐시 계층이 아니라 서버 인메모리 preorder 주문 세션 저장소인 PreorderStore를 의미한다.
- 서버는 쿠폰 목록 조회 시 현재 preorder와 배송 조건 기준의 최대 할인 추천 쿠폰 ID 목록을 함께 내려준다.
- 프론트엔드는 쿠폰 모달을 처음 열 때 선택된 쿠폰이 없으면 서버의 추천 쿠폰 ID 목록을 초기 선택값으로 사용한다.

## 주문 흐름 요약

1. 프론트엔드는 장바구니에서 선택한 cart ID 목록만 서버에 전달한다.
2. 서버는 cart ID를 검증하고 DB에서 상품 정보를 조회한 뒤 서버 인메모리 PreorderStore에 preorder 주문 세션을 생성한다.
3. 주문 확인 페이지는 `preorderId`로 주문 대상 상품 정보를 조회한다.
4. 쿠폰 영역은 `preorderId`와 배송 조건을 기준으로 사용 가능 쿠폰, 비활성화 사유, 추천 쿠폰 ID 목록을 조회한다.
5. 쿠폰 모달을 처음 열 때 선택된 쿠폰이 없으면 프론트엔드는 서버가 추천한 쿠폰 ID 목록을 초기 선택값으로 사용한다.
6. 사용자가 쿠폰을 체크하거나 해제하면 프론트엔드는 현재 선택 중인 쿠폰 ID 목록과 배송 조건으로 `POST /order/preview`를 호출한다.
7. 사용자가 제주도 및 도서산간 지역 여부를 변경하면 프론트엔드는 DB를 업데이트하지 않고, 현재 선택 중인 쿠폰 ID 목록과 변경된 배송 조건으로 `POST /order/preview`를 호출한다.
8. 서버는 preorder, 쿠폰 정책, 서버 시간, 요청의 `couponIds`, `isRemoteArea`를 기준으로 주문 금액, 상품 할인 금액, 배송비 할인 금액, 총 할인 금액, 배송비, 최종 결제 금액을 계산해 응답한다.
9. 2+1 쿠폰이 적용되면 서버는 무료 증정 상품 정보를 `benefitItems`로 응답하고, 해당 상품 정가를 주문 금액과 상품 할인 금액에 함께 반영한다.
10. 프론트엔드는 결제 금액 미리보기 응답의 총 할인 금액으로 "총 n원 할인 쿠폰 사용하기" 문구를 표시한다.
11. 무료 배송 쿠폰으로 기본 배송비와 도서산간 추가 배송비가 모두 무료 처리되면 서버는 해당 배송비 할인액을 총 할인 금액에 포함해 응답한다.
12. 서버는 결제 금액 미리보기 요청이 성공하면 실제 적용된 쿠폰 ID 목록과 배송 조건을 PreorderStore에 저장한다.
13. 프론트엔드는 preview 응답의 금액과 적용/제외 쿠폰 결과만 화면에 표시한다.
14. 사용자가 결제하기를 누르면 프론트엔드는 `preorderId`, `expectedTotalPaymentAmount`를 서버에 전달한다.
15. 서버는 주문 생성 시점에 PreorderStore의 적용 쿠폰/배송 조건을 기준으로 금액을 다시 계산하고, `expectedTotalPaymentAmount`와 일치할 때만 주문을 생성한다.
16. 주문 생성 성공 시 preorder는 한 번 소비된 주문 세션으로 처리하고 PreorderStore에서 삭제한다.
